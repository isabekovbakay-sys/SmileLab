# Публикация SmileLab (Android)

Пошаговая инструкция: от реальных данных до Google Play и обновлений.

## 1. Чек-лист перед выпуском

- [ ] **Данные клиники** в `src/config/clinic.ts`: адрес (город, район, улица, дом, ориентир), координаты (если знаете точно), часы работы и перерывы по дням, способы оплаты. Контакты уже настоящие: +996 507 597 099 (звонки, WhatsApp, Telegram), isabekovbakay@gmail.com.
- [ ] **Telegram**: если у клиники есть @username, впишите его в `contacts.telegram.username`. Ссылка по номеру открывает чат, только если в Telegram разрешено находить вас по номеру, а готовый текст заявки передаётся только по @username.
- [ ] **Врачи** в `src/data/mock/doctors.ts`: ФИО, специализация, языки приёма, дни и часы. Сейчас там условные демо-врачи.
- [ ] **Услуги и цены** в `src/data/mock/services.ts`: цены «от» в сомах, длительность, описания, этапы, FAQ на двух языках. Если цену нельзя назвать заранее, ставьте `priceFrom: null`, и в приложении будет «Цена после консультации».
- [ ] **Тексты** в `src/data/mock/clinicContent.ts`: заголовок главной, принципы работы. Не пишите цифр, которые нельзя подтвердить («98% довольных», «10 лет опыта»).
- [ ] **`isDemo: false`** в `src/config/clinic.ts`. Исчезнут плашки «Демо», заявки начнут сразу открывать WhatsApp клиники с готовым текстом, пропадёт имитация занятости слотов.
- [ ] **Видео для главной** (необязательно): положите `assets/video/hero.mp4` (≤ 5 МБ, без звука, 8–15 с) и укажите в `media.heroVideo: require('../../assets/video/hero.mp4')`. Без видео на главной фирменный фон.
- [ ] **Проверки**: `npm run check` — типы, линтер, тесты.
- [ ] **Политика конфиденциальности**: `npm run privacy:html` → `docs/privacy-policy.html`. Опубликуйте её (например, GitHub Pages: Settings → Pages → Branch `main`, папка `/docs`) и возьмите ссылку для Play Console.
- [ ] **Графика для магазина**: `npm run store:graphics` (см. раздел 6).
- [ ] **Иконки**: если меняли цвета или логотип, выполните `npm run icons`.

> `android.package` = `kg.smilelab.app`. После первой публикации в Google Play его **нельзя** изменить.

## 2. Запуск на телефоне для проверки (Expo Go)

```bash
npm install
npx expo start
```

Установите **Expo Go** из Google Play и отсканируйте QR-код из терминала. Телефон и компьютер должны быть в одной сети (иначе: `npx expo start --tunnel`).

## 3. Сборка через EAS (рекомендуется)

Нужен бесплатный аккаунт на [expo.dev](https://expo.dev).

```bash
npm run build:apk   # APK для прямой установки (профиль "apk")
npm run build:aab   # AAB для Google Play (профиль "production")
```

Скрипт `scripts/build-apk.sh` ставит зависимости, запускает проверки, предупреждает, если включён `isDemo`, просит войти в Expo (`eas login`) и запускает `eas build`.

- При первой сборке EAS предложит **создать ключ подписи**: соглашайтесь. Ключ хранится в EAS, потерять его нельзя, иначе не выйдет выпускать обновления в Google Play.
- `versionCode` ведёт EAS (`appVersionSource: remote`, `autoIncrement`), вручную его менять не нужно.
- На бесплатном тарифе сборка может стоять в **очереди 1–2 часа**.
- Ссылка на готовый файл появится в терминале и на expo.dev → Builds.

### Сборка APK без EAS

- **GitHub Actions**: workflow `.github/workflows/android-apk.yml` собирает APK при push в `main` или вручную (Actions → Android APK → Run workflow). APK лежит в артефактах запуска. Эта сборка подписана **отладочным ключом**: она годится для тестов, но не для Google Play.
- **Локально** (нужны Android Studio / SDK и JDK 17): `npm run build:apk:local`. APK появится в `android/app/build/outputs/apk/release/`.

## 4. Прямая раздача APK

Отправьте APK пациентам файлом или ссылкой. При установке не из магазина:

1. Android попросит разрешить установку из этого источника (браузер или мессенджер): «Настройки → Разрешить».
2. **Google Play Защита** может показать «Приложение заблокировано…» или «Небезопасное приложение». Нажмите **«Подробнее → Всё равно установить»**.

⚠️ Поэтому для пациентов лучше Google Play: даже **внутреннее тестирование** даёт установку по ссылке без предупреждений (до 100 человек). С 2026–2027 годов Google вводит обязательную **верификацию разработчиков** и для приложений вне магазина: неподписанные верифицированным разработчиком APK будут устанавливаться всё труднее.

## 5. Google Play

1. **Аккаунт разработчика**: [play.google.com/console](https://play.google.com/console), единоразово **$25**.
   - **Организация** (клиника как юрлицо): нужен номер **D-U-N-S**, его бесплатно выдаёт Dun & Bradstreet, срок до ~30 дней. В описании будет название клиники.
   - **Личный аккаунт** (созданный после ноября 2023): перед выпуском в продакшн обязателен **закрытый тест с 12+ тестировщиками в течение 14 дней подряд**.
2. **Создайте приложение**: язык по умолчанию — русский, добавьте кыргызский (ky-KG). Тип — приложение, бесплатное.
3. **Заполните разделы** по `store/STORE_LISTING.md`: описание, графика, политика конфиденциальности, реклама (нет), рейтинг IARC, целевая аудитория 18+, Health apps declaration, Data safety.
4. **Сначала внутреннее тестирование** (Тестирование → Внутреннее): загрузите AAB (`npm run build:aab`), добавьте e-mail тестировщиков, отправьте им ссылку. Проверьте запись, звонок, WhatsApp и 2ГИС на реальных телефонах.
5. Затем **закрытое тестирование** (12 человек × 14 дней для личного аккаунта) → **Продакшн** → «Отправить на проверку». Первая проверка обычно занимает от нескольких дней до недели.

## 6. Графика для магазина

```bash
# 1) реальные данные и isDemo: false в src/config/clinic.ts
npx expo export --platform web --output-dir web-dist
npx playwright-core install chromium   # один раз
npm run store:graphics
```

Скрипт снимает по 7 скриншотов 1080×1920 на кыргызском и русском (главная, услуги, услуга, выбор времени, успех, мои записи, контакты) и рисует feature graphic 1024×500. Экран с вводом телефона не снимается. Сейчас в `store/google-play/` лежит графика на **демо-данных**: перегенерируйте её после замены данных.

## 7. Обновления

1. Внесите изменения, выполните `npm run check`.
2. Поднимите `version` в `app.json` (например, `1.0.0` → `1.1.0`). Это версия, которую видят пользователи. `versionCode` EAS увеличит сам.
3. `npm run build:aab` → загрузите AAB в нужный трек Play Console → «Отправить на проверку».
4. Для прямой раздачи: `npm run build:apk` и новая ссылка. Android обновит приложение поверх старого, если подпись та же (тот же ключ EAS).

## 8. Как подключить сервер

Экраны не меняются: источник данных переключается переменными окружения.

1. Реализуйте API по контракту в `src/services/api/apiRepositories.ts`. Форматы JSON — типы из `src/types/domain.ts`:
   - `GET /services`, `GET /services/:id`, `GET /doctors`, `GET /doctors/:id`, `GET /clinic/content`
   - `GET /availability?serviceId=&doctorId=&branchId=&fromDate=&days=&excludeAppointmentId=`
   - `GET /appointments`, `POST /appointments` (409, если время занято)
   - `POST /appointments/:id/cancel`, `POST /appointments/:id/reschedule` (409, если время занято)
2. Создайте `.env` по образцу `.env.example`:
   ```
   EXPO_PUBLIC_DATA_SOURCE=api
   EXPO_PUBLIC_API_BASE_URL=https://api.example.kg
   ```
   Для EAS те же переменные задаются в `eas.json` (`build.<profile>.env`) или в Environment variables на expo.dev.
3. В режиме `api` заявки уходят на сервер, экран успеха пишет «Заявка принята», мессенджер не открывается.
4. Секреты (токены, ключи) в приложение не кладите: всё с префиксом `EXPO_PUBLIC_` попадает в сборку и видно любому.
5. Онлайн-оплата: интерфейс `PaymentProvider` в `src/services/payment/` рассчитан на ELQR, банки и карты. Сейчас подключена только «оплата в клинике».
