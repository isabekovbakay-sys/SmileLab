# Публикация SmileLab (Android)

Пошаговая инструкция: от реальных данных до Google Play и обновлений.

> **Главное правило подписи.** Приложение для пациентов (APK по ссылке и AAB для Google Play) собирается
> **только через EAS**. EAS создаёт и хранит ключ подписи, и все обновления подписываются тем же ключом.
> Локальная сборка (`npm run build:apk:debug-local`) и APK из GitHub Actions подписаны **отладочным ключом**:
> поверх них релиз не установится, пациентам их не раздавайте.

## 1. Чек-лист перед выпуском

- [ ] **Контакты** в `src/config/clinic.ts`: телефон, WhatsApp, e-mail уже вписаны. Telegram: если есть `@username`, впишите его в `contacts.telegram.username` (только с ним Telegram подставляет текст заявки); если Telegram не нужен — оставьте `username: null` и `phone: null`, кнопка исчезнет.
- [ ] **Адрес**: улица и дом на двух языках, район и ориентир — по желанию. Без улицы и дома кнопки 2ГИС и карты скрыты.
- [ ] **2ГИС**: откройте клинику в 2ГИС → «Поделиться» → вставьте ссылку в `twoGisUrl`. **Координаты** — только точные, из 2ГИС или Google Maps.
- [ ] **Часы работы и перерывы** по дням (`workingHours`). Пока все дни выходные, вместо выбора времени приложение предлагает позвонить.
- [ ] **Юрлицо** (`legal`): название ОсОО/ИП, ИНН (14 цифр), юридический адрес — для политики конфиденциальности.
- [ ] **Услуги и цены** в `src/data/clinic/services.ts`: цена «от» в сомах **или** `priceAfterConsultation: true` («Цена после консультации»). Образец формата — в комментарии файла и в `src/data/demo/services.ts`.
- [ ] **Врачи** в `src/data/clinic/doctors.ts`: имя, должность (одинаковая на двух языках), языки приёма, дни и часы.
- [ ] **Тексты** в `src/data/clinic/content.ts`: без цифр, которые нельзя подтвердить («98% довольных», «10 лет опыта»).
- [ ] **Проверки**: `npm run check`, затем `npm run release:check` — пишет по-русски, что ещё не заполнено.
- [ ] **Кыргызский перевод**: `npm run ky:review` → `docs/ky-review.md`, дайте вычитать носителю языка (строки с ⚠ — в первую очередь).
- [ ] **Политика конфиденциальности**: `npm run privacy:html` → `docs/privacy-policy.html` (без юрлица скрипт остановится). Опубликуйте её (GitHub Pages: Settings → Pages → Branch `main`, папка `/docs`) и возьмите ссылку для Play Console.
- [ ] **Графика для магазина**: `npm run store:graphics` на реальных данных (раздел 6).

> `android.package` = `kg.smilelab.app`. После первой публикации в Google Play его **нельзя** изменить.

## 2. Запуск на телефоне для проверки (Expo Go)

```bash
npm install
npx expo start --clear
```

Установите **Expo Go** из Google Play и отсканируйте QR-код. Телефон и компьютер — в одной сети (иначе `npx expo start --tunnel`). Демо-данные: `EXPO_PUBLIC_DEMO=1 npx expo start --clear`.

## 3. Сборка через EAS

Нужен бесплатный аккаунт на [expo.dev](https://expo.dev).

```bash
npm run build:apk       # релизный APK для прямой установки (профиль "apk")
npm run build:aab       # AAB для Google Play (профиль "production")
npm run build:apk:demo  # демо-APK для показа (профиль "demo"), не для пациентов
```

`scripts/build-apk.sh` ставит зависимости, запускает `npm run check`, для релизных профилей — `release:check` (сборка остановится, если данные не заполнены), просит войти в Expo и запускает `eas build`. Та же проверка работает и на серверах EAS (`eas-build-post-install`), даже если запустить `eas build` напрямую.

| Профиль | Что | `EXPO_PUBLIC_DEMO` |
| --- | --- | --- |
| `demo` | APK с демо-данными и плашкой «Демо» | `1` |
| `apk` | релизный APK для прямой установки | `0` |
| `production` | AAB для Google Play | `0` |

- При первой сборке EAS предложит **создать ключ подписи** — соглашайтесь.
- **Сразу скачайте копию ключа**: `eas credentials -p android` → Android → `production` → Keystore → **Download keystore**. Храните файл и пароли у владельца клиники (не в репозитории). Без ключа нельзя выпустить обновление APK, которое встанет поверх установленного.
- `versionCode` ведёт EAS (`appVersionSource: remote`, `autoIncrement`); в `app.json` его нет и вручную менять не нужно.
- На бесплатном тарифе сборка может стоять в **очереди 1–2 часа**. Ссылка на файл — в терминале и на expo.dev → Builds.

### Размер и R8

Релизная сборка сжимается R8 (`enableMinifyInReleaseBuilds`) и убирает неиспользуемые ресурсы (`enableShrinkResourcesInReleaseBuilds`). Видеоплеер удалён, `expo-updates` нет. Нативная часть `@expo/ui` (Jetpack Compose — нужна expo-router только для `Stack.Toolbar`, которого в приложении нет) исключена из сборки, а её JS на Android подменяется заглушкой `shims/expo-ui-stub.js` (`metro.config.js`) — иначе приложение падало бы при запуске. **После первой такой сборки пройдите все экраны на реальном телефоне**: запись до конца, звонок, WhatsApp, Telegram, 2ГИС, «Добавить в календарь», перенос и отмену, смену языка, удаление данных. Если что-то падает только в релизе — это R8; сообщите разработчику.

### Другие сборки (не для пациентов)

- **GitHub Actions** (`.github/workflows/android-apk.yml`) собирает **демо-APK с отладочным ключом** при каждом push и публикует его в Releases с пометкой «ДЕМО — отладочный ключ, не для пациентов». Там же проверяются разрешения (только INTERNET и VIBRATE), манифест, отсутствие демо-данных в релизном бандле, а перед публикацией APK запускается на эмуляторе (выбор языка → главная → запись): падающая сборка в Releases не попадёт.
- **Локально** (Android Studio / SDK и JDK 17): `npm run build:apk:debug-local`. Подписано отладочным ключом — только для проверки на своём телефоне.

## 4. Прямая раздача APK

Отправьте релизный APK из EAS пациентам файлом или ссылкой. При установке не из магазина:

1. Android попросит разрешить установку из этого источника: «Настройки → Разрешить».
2. **Google Play Защита** может предупредить. Нажмите **«Подробнее → Всё равно установить»**.

⚠️ Поэтому для пациентов лучше Google Play: даже **внутреннее тестирование** даёт установку по ссылке без предупреждений (до 100 человек). Google вводит обязательную верификацию разработчиков и для приложений вне магазина.

## 5. Google Play

1. **Аккаунт разработчика**: [play.google.com/console](https://play.google.com/console), единоразово **$25**.
   - **Организация** (клиника как юрлицо): нужен номер **D-U-N-S** (бесплатно, до ~30 дней).
   - **Личный аккаунт**: перед выпуском в продакшн обязателен **закрытый тест с 12+ тестировщиками 14 дней подряд**.
2. **Создайте приложение**: язык по умолчанию — русский, добавьте кыргызский (ky-KG). Бесплатное.
3. **Play App Signing** (подпись приложений в Google Play) — включается при первой загрузке AAB, **соглашайтесь**. Google будет подписывать приложение для пользователей своим ключом, а ключ из EAS станет **ключом загрузки** (upload key). Если ключ загрузки потеряется, его можно сбросить через поддержку Google Play — поэтому копия из `eas credentials` всё равно нужна, но потеря не фатальна.
   - Важно: APK из Google Play и APK из EAS для прямой установки будут подписаны **разными ключами** — поверх друг друга они не обновятся. Выберите один канал для пациентов (рекомендуется Google Play).
4. **Заполните разделы** по `store/STORE_LISTING.md`: описание, графика, политика конфиденциальности, реклама (нет), рейтинг IARC, целевая аудитория 18+, Health apps declaration, **Data safety** (ответы там совпадают с политикой).
5. **Внутреннее тестирование**: загрузите AAB (`npm run build:aab`), добавьте e-mail тестировщиков, отправьте ссылку. Проверьте всё на реальных телефонах.
6. Затем **закрытое тестирование** → **Продакшн** → «Отправить на проверку».

## 6. Графика для магазина

```bash
# данные клиники заполнены, npm run release:check проходит
EXPO_PUBLIC_DEMO=0 npx expo export --platform web --clear --output-dir web-dist
npx playwright-core install chromium   # один раз
npm run store:graphics
```

Скрипт снимает по 7 скриншотов 1080×1920 на кыргызском и русском и рисует feature graphic 1024×500. Сейчас в `store/google-play/` лежит графика на **демо-данных** — в магазин её не загружайте.

## 7. Обновления

1. Внесите изменения, выполните `npm run check` и `npm run release:check`.
2. Поднимите `version` в `app.json` (например, `1.0.0` → `1.1.0`). `versionCode` EAS увеличит сам.
3. `npm run build:aab` → загрузите AAB в Play Console → «Отправить на проверку».
4. Для прямой раздачи: `npm run build:apk`. Android обновит приложение поверх старого, если подпись та же (тот же ключ EAS).

## 8. Как подключить сервер

Экраны не меняются: источник данных переключается переменными окружения.

1. Реализуйте API по контракту в `src/services/api/apiRepositories.ts`. Форматы JSON — типы из `src/types/domain.ts`:
   - `GET /services`, `GET /services/:id`, `GET /doctors`, `GET /doctors/:id`, `GET /clinic/content`
   - `GET /availability?serviceId=&doctorId=&branchId=&fromDate=&days=&excludeAppointmentId=`
   - `GET /appointments`, `POST /appointments` (409, если время занято)
   - `POST /appointments/:id/cancel`, `POST /appointments/:id/reschedule` (409, если время занято)
2. Задайте в `eas.json` (`build.<profile>.env`) или в Environment variables на expo.dev:
   ```
   EXPO_PUBLIC_DATA_SOURCE=api
   EXPO_PUBLIC_API_BASE_URL=https://api.example.kg
   ```
3. В режиме `api` пациент выбирает настоящее свободное время (запись блокирует все свои ячейки), заявки уходят на сервер, мессенджер не открывается.
4. Секреты (токены, ключи) в приложение не кладите: всё с префиксом `EXPO_PUBLIC_` попадает в сборку и видно любому.
5. Онлайн-оплата: интерфейс `PaymentProvider` в `src/services/payment/` рассчитан на ELQR, банки и карты. Сейчас подключена только «оплата в клинике».
